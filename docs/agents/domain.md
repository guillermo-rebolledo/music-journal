# Domain docs

This repo uses a single-context layout with `GLOSSARY.md` at the root
and architecture decision records in `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and any ADRs relevant to the area being explored.
If these files are absent, proceed silently. The domain-modeling skill
creates them as terms and decisions are resolved.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues,
proposals, code, and tests. Note missing concepts for domain-modeling.

## Decisions

Explicitly flag any proposal that contradicts an existing ADR.
Name the ADR and explain why its decision should be reconsidered.
